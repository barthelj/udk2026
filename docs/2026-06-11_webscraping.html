Webscraping – was ist das?

Wir haben uns schon angeschaut, wie man Daten sammeln kann. Dazu haben wir den Netzwerk-Verkehr im Browser angeschaut – sowie entsprechenden Code, um einen Browser nachzuahmen.

Heute geht’s tiefer: In den bisherigen Beispielen hatten wir Glück, dass die Daten gut aufbereitet vorlagen, in Form von json-Files. Das ist natürlich nicht immer so.

Grob kann man die übrigens Fälle unterteilen in:

  1. Informationen liegen gut sichtbar auf einer Webseite vor – und können daher gut ausgelesen werden. Manchmal hat man eine ganze Liste von Webseiten, von denen man die gleichen Informationen strukturiert speichern möchte.

  2. Informationen sind zwar auf einer Webseite sichtbar, aber erst nur teilweise und werden nachgeladen, indem man weiterscrollt oder auf Knöpfe drückt. Wir brauchen also Interaktivität.

Diese beiden Fälle schauen wir uns nacheinander an.

1. Informationen sind auf einer Webseite verfügbar.

Auf einer einfachen Website liegen Informationen immer strukturiert vor. Die Frage ist also vor allem, ob uns die technische Struktur hilft.

Tabellen

Vor allem Tabellen sind dabei sehr komfortabel, weil im html-Code eine feste Struktur für Tabellen definiert ist:

<TABLE summary="This table charts the number of cups of coffee consumed by each senator, the type of coffee (decaf or regular), and whether taken with sugar.">
<CAPTION>Cups of coffee consumed by each senator</CAPTION>
<TR>
   <TH>Name</TH>
   <TH>Cups</TH>
   <TH>Type of Coffee</TH>
   <TH>Sugar?</TH>
<TR>
   <TD>T. Sexton</TD>
   <TD>10</TD>
   <TD>Espresso</TD>
   <TD>No</TD>
<TR>
   <TD>J. Dinnen</TD>
   <TD>5</TD>
   <TD>Decaf</TD>
   <TD>Yes</TD>
</TABLE>

Als Tabelle sieht das dann so aus:

Cups of coffee consumed by each senator
Name Cups Type of Coffee Sugar?
T. Sexton 10 Espresso No
J. Dinnen 5 Decaf Yes

–

Fun fact: Dieses Beispiel hab ich mir nicht ausgedacht, sondern es kommt vom “World Wide Web Consortium”, aus der Beschreibung des html-Standards. Kann man hier alles nachlesen

Beispiel: https://www.scrapethissite.com/pages/forms/

library(rvest)

page <- read_html("https://www.scrapethissite.com/pages/forms/")

raw_table <- page |> 
  html_element("table.table") |> 
  html_table()

Andere, klar definierte Elemente

Praktisch, weil sie oft relevant und gut markiert sind:

  • <h1>, <h2>, <h3>...: Überschriften
  • <a>: Links
  • <li>: “List items”, als Aufzählungen, entweder mit Gedankenstrichen (unordered list: <ul>) oder als nummerierte Liste (ordered list: <ol>)
  • <div>, <section>...: generelle Container / Abschnitte…

Oft gibt es davon aber mehrere. Deshalb sind sie in der Regel in Klassen unterteilt, die mit in der spitzen Klammer angegeben sind, z.B. <h1 class="Postanschrift">.

Praktisch für uns: aus der Kombination des Typs und der Klasse können wir ziemlich gut navigieren.

Mehrere Webseiten (mit gleicher Struktur)

Listen von Webseiten bekommt man auf verschiedenen Wegen:

1. es gibt eine Übersicht der Webseiten (ggf. auch gescraped)

Beispiel: https://museumsdienst-hamburg.de/museen-in-hamburg/

library(rvest)
library(tidyverse)

html <- read_html("https://museumsdienst-hamburg.de/museen-in-hamburg/")

html |> 
  # html_elements("h3") |>
  html_elements(".link-invisible") |> 
  html_text()

museum_links <- html |> 
  html_elements(".post-item") |> 
  html_attr("href")
  
for (museum_link in museum_links){
  print(str_glue("Processing museum with url: {museum_link}"))
  
  museum_html_temp <- read_html(museum_link)
  
  museum_name <- museum_html_temp |> 
    html_element("h1") |> 
    html_text()
  
  print(museum_name)
  
  museum_oeff <- museum_html_temp |> 
    html_elements(".infobox") |> 
    pluck(3) |> 
    html_elements("p") |> 
    pluck(2) |> 
    html_text()
  
  print(museum_oeff)
}

2. “Weiterblättern”

Wir schauen uns nochmal die Scraping-Übungsseite an: [https://www.scrapethissite.com/pages/forms/]. Hier sind die einzelnen Informationen auf vielen Seiten verteilt. Wir müssen also einmal durch alle Seiten durchgehen. Sobald wir auf die zweite Seite blättern, verändert sich die URL zu: https://www.scrapethissite.com/pages/forms/?page_num=2. Wir sehen, dass es insgesamt 24 Seiten gibt. Die URL lässt darauf schließen, dass man page_num= um jede Seite ergänzen kann.

2. Informationen sind nur teilweise sichtbar, müssen nachgeladen werden.

Auch hier gibt es vor allem zwei Möglichkeiten:

  1. Scrollen bis zum Ende der Seite lädt neue Informationen
  2. Klick auf Buttons wie “Weiterlesen” oder “mehr laden” lädt mehr

Für diese Aufgabe eignet sich Python als Programmiersprache mit der Library Playwright. Für die Installation braucht es zwei Schritte: Erstens muss man die Library installieren, z.B. mit pip install playwright. Und zweitens braucht es einen entsprechenden Browser, der “ferngesteuert” werden kann. Diesen installiert man mit playwright install.

Mehr laden durch Scrollen

Beispiel: Programm der fête de la musique Berlin

Mehr laden durch Klick auf Button

Beispiel: Viele Produkt-Seiten wie zum Beispiel Sonnencreme, “Mehr laden”
